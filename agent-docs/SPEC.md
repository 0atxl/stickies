# Stickies: current product specification

This describes the current source, including the approved mechanical cleanup. The owner accepts the current UI/UX and design. [current-milestone.md](current-milestone.md) owns reliability/finishing status; [implementation.md](implementation.md) owns remaining scope and follow-up findings. ## Edge strip

Sources: [edge.rs](../src/edge.rs), [main.rs](../src/main.rs), [motion.rs](../src/motion.rs), [edge-strip.css](../assets/edge-strip.css).

The strip starts dormant. Its working set contains up to four or five active, non-deleted notes, as chosen in Settings, using All Notes' current Recent/Title ordering. The initial sort is Recent; changing it applies to the strip for the running application. Sorting is not persisted.

| State | Visible content and behavior |
|---|---|
| `Dormant` | The default marker shows one 4 × 40 px bar with a subtle shadow and a larger invisible hit area. Pills shows one colored 5 × 14 px pill per visible saved note, rotated with the edge, or one neutral pill when empty. Clicking reveals tabs. Hover reveals them after 140 ms when enabled. |
| `Tabs` | Title tabs plus New note, Search and All Notes buttons. Pointer departure schedules collapse after 350 ms. Escape starts collapse without the leave grace. |
| `Search` | Tabs remain visible beside an input and active-note results, including notes beyond the configured slots. Pointer departure and focus loss leave Search open. |
| `Docked(id)` | Tabs remain visible beside one editable note. Hover and pointer departure do not replace or collapse it. Selecting another tab saves and switches directly. |
| `Reposition` | Expanded strip with a temporary drag preview and Done/Cancel controls. Done persists the position; Cancel or Escape restores the saved position. |

- Closing Search or manually closing a docked note returns to Tabs; the normal leave grace can then collapse it. A docked inactivity timeout saves/closes the note and collapses the strip to its marker. A failed save keeps the editor and tabs open. Search also closes through its button, opening a result, or Toggle strip.
- Quick Search requests 224 px width and always reserves a 128 px results area. Fewer matches leave unused space; the no-match/create action occupies the top of that same area. Query changes do not shrink or expand the outer popup. Content changes share one queued measurement/placement pass; unchanged popup bounds do not request another presentation. Its scrollbar is hidden; wheel scrolling and keyboard selection still reach all matches. The no-match creation label stays short. The owner accepted the fixed-size layout and confirmed no-match jitter was gone on their desktop.
- Quick Search uses a native autohiding GTK popover with the existing panel styling and motion. Outside clicks dismiss it; pointer departure and focus-following pointer movement do not. Escape and control/result actions still close it. Native dismissal may use the first outside click only to dismiss search, requiring another click to activate the underlying application. The owner accepted this tradeoff. Reopening search starts with a blank query.
- Search uses title/body matching and the active collection's sort. Up/Down selects a result and scrolls it into view while focus remains in the entry; Enter opens it. Refreshed results keep their selected row visible after allocation. With no matches and a nonblank query, Enter or the displayed create action makes a note whose title is the trimmed query. An empty query never creates a note.
- Opening a tab/result for a note already in a separate window focuses that window. It does not create a second individual editor for the same note.
- Left/Right use rotated labels on vertical title tabs, 24 px deep and up to 80 px long, shortened to fit the configured count on small screens. Top/Bottom use upright labels on horizontal tabs, 24 px deep with measured, capped widths. Stacked tabs overlap by 8 px. Classic tabs use a 4 px gap. Both layouts reserve 24 px at both ends. Classic only translates the nearest tab 6 px toward the screen center, without neighbor growth, scale or spread. The same button background extends 6 px off screen at rest, replacing the old shadow extension. Padding keeps the title inside its original visible area; translation reveals the extension without a seam. Stacked hover brings the nearest tab to the front and magnifies it by up to 24%. A continuous cosine falloff reaches 1.5 tab pitches; at a title's center its immediate neighbors enlarge by 6%. The stack makes room according to its painted sizes, preserving overlap without a position jump on reversal. Scaling stays anchored to the screen-facing edge on all four sides. Resting centers determine hover targets to avoid feedback from moving bounds. The outgoing title remains in front until hover settles, then normal stack order resumes. Tabs draw from the farthest neighbor toward the hovered title, so an adjacent tab is not covered at both ends by inconsistent ordering. Labels reserve 10 px at each end, clear of the 8 px overlap. Overlapping clicks follow the same drawing order. Long titles truncate without a tooltip. There is no edge note preview, peek renderer, label transfer, peek timer or preview input region. Clicking a tab opens the ordinary docked editor with its existing save guards.
- The utility capsule has contiguous 24 × 24 px New note, Search and All Notes buttons with 16 px icons and faint dividers between cells.
- Title tabs and the utility capsule use compact shadows without perimeter rings. Focus, hover and selection add no decorative outline or tint. Minimal retains its static note-color stripe. The hover wave is unchanged. Titles retain their 11 px font and stay in their tab on hover.
- A decorative arrow joins Search/docked content to its origin. If the selected tab falls beyond the sheet's arrow range, placement moves the sheet just enough to align the arrow, then clamps to the screen. For a visible docked tab its origin follows that note's current position; overflow notes use the available origin or cluster center. It has no interaction role.
- Marker dragging in Dormant saves its along-edge position on release. Settings Reposition previews dragging without writing until Done. A failed Done keeps the preview and error for retry or cancellation. DND or closing All Notes cancels Reposition. Entering it first saves/closes any docked note; a failed save blocks entry.
- Reveal uses a shared 160 ms slide/fade; collapse uses 110 ms. The bar, all tabs and utilities use one progress value, including reversal, with no per-tab stagger. Search/docked panels and their arrow fade over 120 ms. Switching between docked notes keeps the sheet opaque, retains its dimensions and keeps its position when the arrow can reach the new tab, and crossfades the two editor children over 120 ms. The existing save/release guards run before switching; the incoming session loads before the current view is released. The outgoing editor cannot receive input and is removed after the transition. Repeated switches, closure and reduced motion clean up the outgoing child. Reopening the same Search panel during its outgoing fade reverses from its painted opacity, with the arrow sharing that opacity. Hover uses a frame-clock follower in the existing motion helper, covering 99% of the remaining distance in 120 ms and stopping within 0.001 of its target. New pointer positions update the destination of the running callback instead of restarting an animation. Its first frame uses the pointer-event timestamp so an idle clock cannot consume the entrance. Motion reverses from the painted progress; leave grace waits for reveal to finish.
- Custom motion uses opacity/transforms inside stable geometry. It respects Reduce motion and GTK animation settings; Reposition settles strip motion and returns hover scale to its resting value. Typing settles an unfinished Search panel fade. Input uses final tab bounds during reveal and retains them through collapse, with the existing stable 20 px hit allowance and a 7 px dormant bar hit allowance.
- Two Layer Shell windows use namespaces `stickies-strip` and `stickies`, reserve no desktop space (`exclusive_zone(-1)`), and keep a screen-sized extent across states. Transparent space outside their input regions passes pointer input through.
- Transient content uses Layer `Top` when `hide_in_fullscreen` is true and `Overlay` otherwise. A docked note uses `Overlay`. This is a layer policy; there is no explicit fullscreen-window detector.
- With `hide_in_dnd`, Omarchy DND hides the strip and transient panel while preserving an open docked note. Detection requires `OMARCHY_PATH` and reads `~/.local/state/omarchy/notifications.json`; missing/invalid state means false. Other desktops have no DND provider.
- Dormant surfaces take no keyboard focus. Explicit opening requests focus, then returns to on-demand focus after activation. Hover alone does not request exclusive focus.
- The first valid GDK monitor is selected at startup and explicitly assigned to both layer windows. The strip retains that monitor while available, irrespective of pointer movement or list reordering. Removal selects the first valid remaining monitor in GDK list order. Geometry uses its logical width/height with an output-local origin of zero, without adding desktop coordinates or multiplying by scale.
- Monitor-list, invalidation, geometry and scale notifications update tab bounds and clamp placement. Native layout and final widget allocation changes on both layer windows schedule a coalesced final placement pass. These observers do not request recurring frames. Output replacement temporarily unmaps both windows while retaining the docked editor and Search query/results/selection. Search recovery waits for widget/native allocation, without an exclusive-focus request. New recovery cancels obsolete queued work. With no output, both windows remain hidden even through ordinary visibility refreshes; docked inactivity cannot close the retained editor during suspension. Recovery restarts its inactivity interval. Save guards and shared buffers remain unchanged.
- Existing minimum layout sizes remain. Docked notes need at least 300 × 280 logical pixels plus the adjacent strip and gap. Outputs below the layout minimum cannot keep every control visible. Clamps avoid negative placement and invalid resize ranges; no compact layout or fallback UI is provided. The owner confirmed resolution placement, accepted fixed-size Search and confirmed no-match jitter was gone. Focus previously passed. Multi-monitor behavior remains unverified. Temporary geometry diagnostics have been removed; no renderer override is enabled by the app.
- Intended compatibility is Wayland broadly. The implementation requires `zwlr_layer_shell_v1` v4+ through gtk4-layer-shell because OnDemand keyboard focus was added in v4. Before constructing layer windows, startup checks protocol availability/version and prints a diagnostic on failure. No Hyprland IPC or desktop-configuration mutation is used by production code. Unsupported protocol environments have no fallback. Hyprland is the current testing environment; earlier isolated Sway checks do not verify the final build or other compositors. See the staged compatibility work in the roadmap.

## Note windows and editing

Sources: [editor.rs](../src/editor.rs), [main.rs](../src/main.rs), [note_session.rs](../src/note_session.rs), [note_controls.rs](../src/note_controls.rs).

- At most one note is docked. Several different notes can have separate windows; reopening an existing separate note focuses it. Popping out a docked note transfers its view without removing its collection membership.
- Individual editors start at 320 × 376 px and request a 300 × 280 px minimum. Docked resizing is clamped to available screen space and uses the corner appropriate to the edge. Separate windows are undecorated ordinary GTK top-levels; the header supports native movement and the existing corner input requests native resizing. A subtle grip appears in that corner only while the pointer is over the note. They become resizable after their initial monitor-enter event. Floating placement is controlled by the compositor. Separate notes have a 40 × 14 px native WindowHandle in the existing top margin, with a subtle grip and grab cursor. It does not overlap the title or add an editing mode.
- Title and wrapped, scrollable body are editable. The header contains only title and Close. The reserved footer is one opaque, theme-colored capsule. Its normal controls are Color, Text, Checklist, Always open and More. A homogeneous Stack keeps its outer dimensions fixed when selection formatting replaces those controls. Color retains the eight-column, two-row palette. Aa shows samples in Virgil/Inter/JetBrains Mono/Kalam with full-name tooltips, plus S/M/L. Whole-note Regular/Bold controls and setters are removed; existing stored whole-note weight is retained only for appearance compatibility.
- Both editors and the All Notes Sort menu share note-menu colors, corners, spacing and subtle hover fills. Sort keeps its two choices in left-aligned rows. Note menus share icons and selected styling. More is a flat compact panel: four canvas samples without a heading, bullet/numbered list icons for individual notes, then icon-and-label actions. Copy and Open away use short labels; full action names remain in tooltips/accessibility labels. Delete is separated at the bottom. More opens toward the screen interior for docked edges and to the left for detached notes. Nonmodal popovers permit direct switching in one click and dismiss when clicking elsewhere in the editor. Archive remains exclusive to All Notes.

- The individual pin glyph means **Always open**: a per-view, non-persistent inactivity override. It does not change note ordering or request compositor pinning/always-on-top. Close remains available while enabled.
- Only docked editors have an inactivity timer. Off disables it; otherwise the selected 1/2/5-minute interval starts when opened. Keys, clicks, scroll, pointer-enter, pointer motion and note-control changes count as activity. A stationary pointer alone does not repeatedly reset it.
- Always open cancels the timer; disabling it starts a fresh interval. Changing the timeout restarts/cancels an existing docked timer immediately. Separate windows and All Notes have no inactivity timeout.
- In an individual editor, Escape dismisses footer popovers or clears the body selection first, returning the capsule to normal controls. A subsequent Escape closes the note. With no popover or selection, Escape closes it immediately. Close still observes save/removal guards.
- Saved checklist lines beginning `- [ ] ` or `- [x] ` display native check buttons in active editors. The GTK buffer contains the checkbox anchor and item text, with no invisible marker characters. Completion and any formatting on the serialized prefix belong to the anchor. Saving, clipboard transfer, history and formatting offsets reconstruct the existing plain-text markers. Toggling updates completion; completed item text uses a font-sized strike stroke and muted theme ink. Archived previews use the same representation without allowing changes. No anchor/widget objects are stored.
- The Checklist footer toggle adds/removes checklist mode on the current line. Embedded checkboxes toggle completion. Bullet and numbering controls toggle the current line's prefix. Numbering removes any leading `u32` prefix followed by `. `, including continued items; otherwise it inserts `1. `. Enter without Shift continues a recognized list, using an unchecked next checklist item and incrementing numbers. An empty list item ends the list. Backspace at the checklist prefix removes it. These controls are not a general Markdown renderer.
- Active views of the same note share one title buffer, body buffer, style, color, pin state and save owner. A change in All Notes or an individual window is immediately available to the other live view.

- Both body editors have no editing bar, floating selection popup or Find in note. While editable body text is selected, B/I/U/S replace the normal controls in the existing footer capsule. The switch has no animation and depends on the current buffer's selection Boolean, not cursor geometry or focus. Formatting clicks retain the selection. Clearing selection restores the normal page; archived views never show formatting. Switching buffers disconnects the old selection notifications. B/I/U/S use a selected fill when the whole visible selection has that mark; mixed selections remain inactive. Mark and selection changes refresh these states without moving or animating the capsule. Titles remain plain text and do not offer inline formatting. Undo/Redo remain off the footer. The existing native right-click menu entries in body and title editors use the shared custom history, with availability refreshed when the menu opens and while it is open. Keyboard shortcuts remain unchanged. Ctrl+B/I/U and the capsule reuse the existing formatting handler; Ctrl+Z undoes, Ctrl+Shift+Z and Ctrl+Y redo. The native TextView paints readable underline/strike strokes, preserving tags, stored spans and history. Decoration starts from a logical visible line without coordinate hit-testing. Checkbox toggles preserve the text caret/selection; a collapsed caret before the checkbox anchor moves to the item text before native editing. Copy exports plain text with textual checklist markers. GTK's formatting transfer for pasting within the same shared note remains available, including keyboard-anchor copy/cut ranges. The native emoji chooser uses compact UI typography, eight-column emoji grids and a 180 px results-height cap. It opens beside the sheet toward the screen interior for docked notes, preferring the left side for pop-outs and All Notes, with GTK screen-edge adjustment. The context menu and footer panels close when it opens.

- Shared sessions keep up to 100 custom text/formatting history states, including title edits. Both title and body shortcuts use that shared stack; GTK's own undo is disabled for these editing buffers. History is session-local and excludes presentation anchors. Continuous, adjacent insertion or deletion groups up to 100 Unicode characters. A pause of at least one second, a typed newline, a change of edit direction or field, or cursor/selection movement ends the group. Clipboard/drop operations, formatting marks, list-prefix and checkbox toggles and list continuation are isolated steps. The grouping clock is injectable; production uses monotonic elapsed time. Undo restores text and formatting together and places the cursor at the changed range. A new edit after undo clears redo. List-prefix changes preserve formatting on the item text. A formatting-load failure blocks saving that session.
- Selecting an emoji keeps the native chooser available for another selection in title and body editors. GTK still inserts the emoji and updates recents; its selection-triggered close restores the chooser with its search and scroll position. Escape and outside-click dismissal remain native. Insertion continues at the updated caret through the existing editing/history path. Recorded native checks passed repeated title/body insertion, search/scroll retention, skin-tone selection, recents, dismissal, history and persistence. Complete keyboard-only navigation and frame-level flicker remain unverified.
- Hover labels are concise. Redundant checkbox, date and resize hints are omitted; screen-reader labels remain on icon actions. Compositor shortcut examples live in README, not Settings.

## All Notes

Sources: [manager.rs](../src/manager.rs), [main.rs](../src/main.rs), [storage.rs](../src/storage.rs), [all-notes.css](../assets/all-notes.css).

- One reusable ordinary application window, default 720 × 500 px, minimum request 680 × 480 px, with a 240 px list column. Opening an existing window presents it with its current state.
- A newly created All Notes window starts in Active with an empty search and **no selected note or preview**, even when notes exist. Its preview says “Choose a note.” Clicking or keyboard-selecting a row opens it. Refresh retains a chosen note only while it remains in the results; it does not select a replacement automatically. Creating a draft opens its editable preview while leaving rows, list selection, filter and search unchanged. Its row is selected after the first successful non-blank save. Deletion Undo returns to Active with an empty search and selects the restored note when it belongs to Active. Back to notes also uses Active. The show-all-notes action presents an existing window with its current state or creates one with these defaults.
- All includes active and archived notes; Active excludes archived; Archived shows only archived. Every collection excludes deleted notes. Search matches title/body within the selected collection.
- When no saved, non-deleted notes exist across Active and Archived, the collection filters and list column, including its divider, are hidden. The welcome content is centered across the workspace, says "Welcome to Stickies", offers "Create your first note" and explains access through the edge marker on a separate line. Its explanatory text wraps within a bounded width with centered alignment. Unpublished drafts do not make filters or the list column appear. Empty search results and an empty collection keep both when saved notes exist elsewhere; deleting the last note hides them, and Undo restores them.
- Recent orders All/Active by pinned first, updated time descending, stored `sort_order` ascending, then ID descending. Title orders them by pinned first, title with SQLite `NOCASE`, then updated time/ID descending. Archived omits pinned priority. The sort choice survives closing/reopening All Notes within the same process, but resets to Recent at application restart.
- Active selections edit the shared session directly. Archived selections are read-only snapshots with completed-line styling; they must be restored before editing, pinning or popping out.
- The reserved preview footer contains Color, Text, Checklist, ordering Pin, Pop out and More. Color and Text reuse the individual editor popovers, including the eight-column palette and font family/size. More contains four canvas samples above one row of three action icons: Copy, Archive/Restore and Delete, with full-name tooltips and accessible labels. Restore replaces Archive for archived notes. Editable selections replace the normal footer with B/I/U/S in the same capsule. Styling changes only the selected note through its shared session and save handlers. The large inline tools panel and its compact/wide breakpoint are removed. Archived selections disable every control except Copy and Restore. Copy text copies the current body, including checklist markers.
- Ordering Pin persists on the note and affects All/Active and the edge. It is distinct from an individual editor's Always open toggle.
- Archive preserves the note and removes it from Active/the edge. Restore returns it to Active. Delete is soft deletion; a six-second Undo toast restores its previous collection and pin state. All Notes uses a compact toast sized to its content, retaining the native dismiss control, queue and timeout behavior. Archive/Delete close matching individual views through the coordinator after the initiating save guard.
- Individual Delete uses the same collection mutation path and shared save guards. It closes the note and shows one six-second Undo toast on the existing strip surface. The toast is clamped beside the current strip, has only "Note deleted" and Undo, replaces any earlier toast, and accepts input only within its bounds on that surface. It uses Overlay and survives DND like a docked note. The existing motion helper provides a 120 ms fade, skipped for reduced motion. Undo uses the existing storage restore operation. All Notes retains its own toast.
- A selected active note has saving/saved/error feedback. Individual notes show save-error toasts without a routine saved indicator. Empty collections/searches offer Create a note, Back to notes or Clear search as appropriate.
- Closing All Notes releases its editor and leaves other note windows available. Failed text/color saves or blank-note removal block closing/replacing that editor.

## Settings

Sources: [settings.rs](../src/settings.rs), [manager.rs](../src/manager.rs), [main.rs](../src/main.rs), [autostart.rs](../src/autostart.rs).

The gear toggles one scrollable Settings drawer inside All Notes. Its width is 260 px; an explicit breakpoint overlays it, with the native scrim covering both filters and notes, at widths up to 979 px. At wider widths it occupies sidebar space.

| Section | Implemented controls |
|---|---|
| Appearance | Minimal/Paper/Playful; System/Light/Dark when Minimal is selected. Font and canvas choices belong to the selected note editor, not Settings. |
| Edge strip | Left/Right/Top/Bottom; Top/Center/Bottom on vertical edges or Left/Center/Right on horizontal edges; Reposition beneath Position; Visible notes 4/5; Tabs Classic/Stacked; Marker Pills/Bar. Presets save offsets 0/0.5/1. |
| Behavior | Docked note timeout: Off / 1 / 2 / 5 minutes; Reduce motion, Hover to reveal and Launch at login switches at the bottom. Fullscreen/DND policies are config-file-only. |

- Theme previews appear first, without a redundant Appearance heading. The choice rows are Mode, Edge, Position, Visible notes, Tabs, Marker and Auto-close. Position includes Reposition beneath its choices. Edge strip and Behavior section headings are removed.
- Decorative pressed/focus/selected rings remain removed. Footer/menu options and Settings buttons use a subtle gray hover fill. Settings separates choice rows with 16 px gaps and gives Edge, Position and Auto-close full-width choices below their labels. Theme previews retain their size, and Reposition has a button fill and boundary. Checkmarks, switch positions, selected value fills, collection filters and selected note/search rows remain to identify actual state. Static paper edges, control boundaries and shadows remain.
- Changes validate and save config before replacing live application config, then refresh open views. Settings changes are blocked during Reposition and after an invalid/unreadable startup config.
- Errors are displayed. Position, timeout and Appearance controls resynchronize to the accepted live config after rejected writes. Appearance synchronization restores theme, Minimal mode visibility, Reduce motion and samples under a signal guard, without submitting another save.
- App Reduce motion forces GTK animations off. Turning it off releases the application override so GTK follows the current system preference. Unrelated settings writes leave that preference alone; rejected writes do not change it.
- There is no Settings control for true strip enablement, default new-note color, or shape. There is no About section. Corresponding stored keys below remain available where implemented.
- `launch_at_login` reconciles `$XDG_CONFIG_HOME/autostart/dev.stickies.Stickies.desktop` on valid startup. True installs the supplied entry (`Exec=stickies`); false removes it. This does not establish that an installed login launch has been verified.

## Themes and note appearance

Sources: [appearance.rs](../src/appearance.rs), [app.rs](../src/app.rs), [config.rs](../src/config.rs), [ui_assets.rs](../src/ui_assets.rs), [all-notes.css](../assets/all-notes.css).

| Theme | Note surface and theme-default content font |
|---|---|
| Paper (default) | Opaque warm paper, colored left accent, soft shadow; default Ticket/Torn treatment tears the bottom edge. Virgil. |
| Minimal Light | Opaque white, colored top accent, smooth rounded rectangle. Inter. |
| Minimal Dark | Opaque dark slate, colored top accent, smooth rounded rectangle. Inter. |
| Playful | Opaque fill from the note's color, wavy edges, dark outline and offset shadow. Virgil. |

- Minimal's System mode reads GTK's prefer-dark flag/theme name. Light/Dark override it. Paper and Playful do not gain a separate dark appearance from this preference.
- Font family, size, canvas and color are per-note controls available in individual docked/separate editors and the All Notes selected-note editor. Both share live changes and persistence. Font choices are Virgil, Inter, JetBrains Mono and Kalam. New notes follow their theme font until a family is chosen. Size and weight apply to title and body.
- S/M/L body sizes are 14/17/20 px in every theme. Titles are 27/30/33 px in Paper/Playful and 25/28/31 px in Minimal. New styles default to Medium with weight 400. Previously saved whole-note bold uses 700, without a UI control.
- Plain/Dots/Grid/Ruled patterns work in all themes. New notes use Plain; each note stores its own choice. Optional stored shape overrides also resolve over the global shape, but there is no shape picker. Minimal always draws the smooth rectangle; Paper Square is smooth and Ticket/Torn currently share the bottom-tear path; Playful draws waves on all edges.
- The shared 16-color palette is stored as `yellow`, `blue`, `purple`, `green`, `orange`, `red`, `pink`, `lime`, `teal`, `cyan`, `indigo`, `magenta`, `brown`, `gray`, `black`, `white`. The original four appear as Amber, Blue, Lilac and Sage. Color supplies list/edge markers, Paper/Minimal accents and Playful fill; there is no separate Playful fill preference.
- Bundled Virgil, Inter, JetBrains Mono and Kalam Regular/Bold TTF files are cached under `$XDG_CACHE_HOME/stickies/fonts` and registered with Fontconfig. An individual font failure logs a warning and registration continues; resource-registration failure can still stop UI initialization.

## Configuration

Source: [config.rs](../src/config.rs); consumers are the modules above. Path: GLib's user config directory plus `stickies/config.toml` (normally `$XDG_CONFIG_HOME/stickies/config.toml`). Enum strings use lowercase.

| Key | Default | Accepted values / current effect |
|---|---|---|
| `edge` | `right` | `left`, `right`, `top`, `bottom`; strip anchor/orientation. |
| `marker_offset` | `0.5` | Finite 0–1; along-edge position, with placement clamping. |
| `edge_hover_enabled` | `true` | Boolean; permits hover reveal. False still permits click/action reveal. |
| `launch_at_login` | `false` | Boolean; reconciles the autostart desktop entry. |
| `theme` | `paper` | `minimal`, `paper`, `playful`; legacy `glass` loads as Minimal. |
| `appearance` | `system` | `system`, `light`, `dark`; controls Minimal's mode. |
| legacy `font` | absent | Read for startup migration into existing note styles, then omitted on save. |
| legacy `paper` | absent | Read for startup migration into notes without a pattern override, then omitted on save. |
| `shape` | `ticket` | `square`, `ticket`, `torn`; default shape subject to theme drawing rules. |
| `tab_layout` | `stacked` | Classic uses a 4 px gap; Stacked overlaps by 8 px. Legacy adjacent/overlapping values load. |
| `marker_style` | `bar` | `dots` renders Pills; `bar` renders Bar. Independent of tab layout. |
| `visible_notes` | `4` | 4 or 5; Settings saves this limit, and strip queries and horizontal sizing use it, including while a note is docked. |
| `inactivity_seconds` | `120` | Saves accept 0, 60, 120, 300; docked timeout only, 0 means Off. |
| `reduced_motion` | `false` | Boolean; suppresses application animations alongside system settings. |
| `hide_in_fullscreen` | `true` | File-only Boolean; transient Top versus Overlay layer policy. |
| `hide_in_dnd` | `true` | File-only Boolean; Omarchy DND visibility policy. |
| legacy `font_size` | absent | Optional unsigned integer accepted on input, ignored, omitted on save. |

- Missing config creates/saves defaults. Missing keys in an existing file use these defaults. Unknown keys, invalid enums/types and invalid validated values are rejected.
- On load, legacy custom timeouts in 30–1800 seconds other than 60/120/300 normalize to 120 in memory. Loading alone does not rewrite an existing file unless it contains retired choices. Other unsupported durations reject the config.
- Valid configs containing retired `white_paper` entries are saved atomically without those entries. Other preferences retain their accepted values.
- Invalid/unreadable startup config logs an error and uses defaults for that run, preserves the existing file, blocks config writes and skips autostart reconciliation.
- Saving writes `config.toml.tmp`, syncs the file and renames it over the destination. The code does not sync the parent directory.
- Per-note style is TOML in SQLite, with `text_size=medium`, optional `font`, `paper` and `shape` absent by default. Size accepts small/medium/large; pattern/shape use the enum values above. Legacy `text_weight` accepts regular/bold; regular is omitted on save, while existing bold is preserved so style edits do not reset old notes. There is no whole-note weight UI or setter. Missing fields default; unknown fields reject. Per-note `font` is now active and persisted. At startup, legacy global font/paper values migrate transactionally into existing notes before removing their config keys. Global font wins over formerly ignored legacy note font entries; existing pattern overrides remain. Archived and deleted notes are included. Migration failure stops startup without removing the old config. The database schema stays at version 4.

## Actions and shortcuts

Sources: [cli.rs](../src/cli.rs), [main.rs](../src/main.rs), [settings.rs](../src/settings.rs).

GApplication ID/session-bus name is `dev.stickies.Stickies`. Four parameterless `gio::SimpleAction`s are exported through `org.gtk.Actions` at `/dev/stickies/Stickies`.

| Action / CLI flag | Behavior | Settings example |
|---|---|---|
| `new-note` / `--new-note` | Create a blank draft with a persistent random palette color different from the previous new note, dock it and focus its title. | `bind = SUPER, N, exec, stickies --new-note` |
| `search` / `--search` | Open/focus edge Search. If already open, keep its query. | `bind = SUPER, slash, exec, stickies --search` |
| `toggle-strip` / `--toggle-strip` | Reveal/focus a dormant strip; otherwise cancel Reposition, save/close docked content, close Search and collapse. | `bind = SUPER, T, exec, stickies --toggle-strip` |
| `show-all-notes` / `--show-all-notes` | Open or present the single All Notes window. | `bind = SUPER, A, exec, stickies --show-all-notes` |

- With a primary instance running, GApplication forwards the invocation over D-Bus and the secondary exits. Without one, it initializes the UI and then performs the requested action. Plain launch initializes a dormant strip; plain repeated launch does nothing when application windows already exist.
- At most one distinct action flag is accepted per invocation; repeating the same flag is accepted. Unknown flags and combined distinct actions fail. Actions that would replace a docked editor retain it on a failed text/color save.
- UI assets initialize in the primary activation path. No in-app global key capture, automatic Hyprland config editing or conflict detection exists. Bind lines are examples to copy and adapt; they do not reserve keys by themselves.
- Local keys include individual-note layered Escape, edge-state Escape, Search Up/Down/Enter and list-editing Enter/Backspace as described above. There are no registered global accelerators.

To inspect and activate the exported actions while Stickies runs:

```sh
gdbus call --session --dest dev.stickies.Stickies \
  --object-path /dev/stickies/Stickies --method org.gtk.Actions.List
gdbus call --session --dest dev.stickies.Stickies \
  --object-path /dev/stickies/Stickies --method org.gtk.Actions.Activate \
  new-note '[]' '{}'
```

Replace `new-note` with another action name. The empty parameter array matches their parameterless registration. These commands document the exported interface; this documentation pass does not constitute a runtime check.

## Data and saving

Sources: [storage.rs](../src/storage.rs), [note_session.rs](../src/note_session.rs), [main.rs](../src/main.rs), [migrations](../migrations).

- Notes are local SQLite data at GLib's user data directory plus `stickies/notes.db` (normally `$XDG_DATA_HOME/stickies/notes.db`). Database opening creates the parent directory and applies transactional migrations through schema version 4; a newer schema is rejected.
- Stored note fields are ID, title, body, color, pinned, `sort_order`, created/updated timestamps and nullable archived/deleted timestamps. Styles live in a separate `note_styles` table as TOML. No example notes are inserted at startup.
- New notes from the strip, All Notes, search creation or the new-note action choose a random color from the existing 16-color palette, excluding the color stored on the most recently created note when one exists. The chosen color is stored once; existing notes and manual color choices are preserved. Blank creation inserts a draft for editing. Drafts are excluded from edge tabs and their order/configured slot limit, the marker, All Notes rows/order/counts/list selection and every search result. Search creation with a non-whitespace title inserts a normal visible note immediately. Existing blank notes remain visible.
- Drafts use `created_at = -1` in the existing schema 4. The first successful title/body save with non-whitespace content replaces that marker with a real creation timestamp and assigns the usual Recent order in the same SQL update as text and formatting. Failed saves keep the draft hidden and the editor open. Style, color and pin changes alone cannot publish a blank draft. Once published, clearing its content never makes it a draft again. The docked arrow follows the published note's tab.
- Text/color edits save after 750 ms of quiet time through one shared session; further edits reset the debounce. Per-note style and ordering-pin changes write immediately.
- Title/body/color saves update the timestamp and refresh ordering/edge data. Failed text/color saves retain dirty buffers and display an error. Close, switch, dock replacement and initiating archive/delete operations flush first and stop if that flush fails. Failed style/pin writes retain the previous preference and report the error.
- An active draft still whitespace-only in both title and body is soft-deleted when its last editing view leaves. Other shared views keep it alive. Existing blank notes and published notes remain. Save/cleanup failures retain the view for retry. On startup, storage transactionally removes remaining unpublished draft rows and their styles before loading any list. This also removes blank drafts left by a crash or forced exit without removing pre-existing blank notes.
- Checklists persist as textual markers. No child-anchor objects are serialized. Schema 4 adds `notes.formatting`, a JSON array of bold/italic/underline/strike spans using Unicode character offsets in the plain body. Body and formatting save in one SQL update. SQL search uses literal `instr` matching with GLib Unicode case folding of title, body and query through a connection-local SQLite function. Folding includes case expansions such as `Straße`/`STRASSE`; it preserves accents and adds no normalization. Ordering still uses SQLite `NOCASE`.
- Storage uses a synchronous connection on the UI thread. The application does not configure WAL or a busy timeout and has no sync transport, accounts or application-level encryption.
- SIGTERM, SIGHUP and SIGINT use GLib Unix signal sources to request normal application shutdown. Shutdown flushes every active shared note session before releasing its views, logs each failed flush with the note ID and error to stderr, and exits even after a failed write. GTK session registration is enabled; session-end notifications that GTK receives use the same shutdown path. SIGKILL, crashes and session termination without a delivered notification or catchable signal cannot flush pending text.
