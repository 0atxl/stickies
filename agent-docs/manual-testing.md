### Confirmed defects and test corrections

1. **P2 product defect, native Search placement on initialization.** On fresh `--search` startup, the native popup appears at the top-left on all four configured edges. The new regression records native position `(0, 1)` versus requested panel `(1016, 484)` on Right. Reproduce on the environment above with a 12-note fixture and `stickies --search`. See [popup creation](../src/edge.rs#L433), [opening](../src/edge.rs#L1755), [placement](../src/edge.rs#L2322) and [regression](../src/edge.rs#L3390). A later strip click after earlier popup/editor activity placed Search correctly, so the finding is about initialization/lifecycle, not every opening.
2. **P2 product defect observed on Sway, native Search keyboard routing.** With the popup mapped, `wtype` input did not change the query or activate a result, through fresh CLI, existing-process CLI and strip-click paths. Clicking the correctly positioned entry did not recover typing. The same native input tool edited titles/bodies and exercised emoji/history/checklists successfully. Escape could close the strip-click popup. See [opening/focus](../src/edge.rs#L1755) and [key controllers](../src/edge.rs#L1261). At baseline, physical-keyboard confirmation was pending and navigation/native unmatched-query creation were failed or unverified. Their subsequent results are recorded above.

At baseline, the suspected repair area was Search popover parenting/allocation/map/focus ordering in `edge.rs`. The proposed scope required separate approval to correct placement/input while preserving native outside-click dismissal, accepted click consumption, styling/motion and hover-to-reveal, then rerun affected checks with the same small fixture and four edges. The separately authorized follow-up above records the confirmed cause and repair.

The existing typing-history test initially failed at the hidden-marker assertion. A main-loop drain did not fix it. Source inspection of GTK's IM commit path and successful real typing established that the test's `emit_insert_at_cursor` resolved the insertion iter before the application's `begin-user-action` caret correction. The test now brackets that insertion with the same user-action boundary as real GTK input. All original text/caret/history assertions remain; the corrected test passes. No product workaround was added.

The inherited-motion test failed its initial expectation that changing `org.gnome.desktop.interface` changes GTK's inherited animation setting. Headless Sway with a private bus/keyfile GSettings did not provide that desktop-settings bridge. The test was not weakened. App-controlled reduced motion and its persistence passed separately. Hyprland backend failure and this preference failure are test-environment limitations.

New tests are [welcome/colors](../src/manager.rs#L1284), [native Search placement](../src/edge.rs#L3390), [timeout/reduced motion](../src/main.rs#L812) and [schema 3/slot boundaries](../src/storage.rs#L546). The native Search test retains the position assertion that failed at baseline and passed after the fix. All GTK additions are ignored by default and require the isolated setup described above.

## Isolation and reporting

Use disposable XDG data/config/cache directories, an isolated Wayland display and a private session bus. Different XDG paths alone do not isolate a GApplication instance. Never use or alter the owner's saved notes or desktop configuration. Retain failure fixtures and stderr until investigated. Avoid historical review launchers that stamp schema 3 after applying all migrations.

For each authorized check, record the commit/diff, compositor and version, native library versions, display sizes/scales, fixture, result and remaining limitation.
