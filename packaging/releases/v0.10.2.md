# Stickies v0.10.2

Package version: 0.10.2. This release reduces the number of files extracted or installed by the Windows and Arch packages.

## Changes

- Windows stock GTK icons are combined into one resource file, preserving native-control icons and fallbacks. Unrelated GTK demo icons are excluded.
- Third-party notices on Windows and Arch are consolidated into attributed documents. Original text, dependency associations and source provenance are retained.
- Windows build-only image-loader import libraries are excluded from the runtime ZIP.
- The Windows application executable is stripped. An optional symbols ZIP retains its unstripped executable, identity record and notices for crash investigation.
- Required native DLLs, image-loader formats, cursor fallbacks and the existing note interface are retained.

These changes reduce extraction operations and bytes. Extraction time and RAM effects have not been benchmarked.

## Downloads and installation

**Windows x86_64:** download `stickies-windows-x86_64.zip`, extract the entire ZIP, then open `bin\stickies.exe`. Keep its runtime folders together, including `share/stickies-icons.gresource`. Rust and MSYS2 are not required. The source and symbols ZIPs do not need extraction to run the app. Quit before replacing an existing bundle. User notes/settings normally remain separately under `%LOCALAPPDATA%\stickies`. Re-enable Launch at login if the bundle moves.

**Arch Linux x86_64:** install `stickies-0.10.2-1-x86_64.pkg.tar.zst` with `sudo pacman -U ./stickies-0.10.2-1-x86_64.pkg.tar.zst`, or update through AUR `stickies` or `stickies-bin`. Use an up-to-date Arch system with a Wayland compositor supporting Layer Shell v4+. Quit before upgrading. User notes/settings are retained.

**Cargo:** install native build prerequisites from the README, then run `cargo install stickies --version 0.10.2 --locked`. Desktop launcher/icon installation is a separate documented step.

Matching sources, original notices, build records and `SHA256SUMS` accompany the packages. These downloads are unsigned. Checksums detect changed bytes but do not provide a publisher signature.

## Verification and limits

Static checks and Linux compilation cover the cleanup. Fresh Windows and Arch packaging and downloaded artifact inspection must pass before publication. No tests, app sessions or performance benchmarks are authorized for this release task. Package integrity checks do not establish runtime or visual acceptance of the new Windows icon-resource loading.

The Linux edge requires Wayland Layer Shell v4+. GNOME without Layer Shell, X11 and macOS are unsupported. Mixed-DPI/multi-monitor behavior, actual login/session-end behavior, accessibility and controlled failed-save scenarios retain the documented verification limits.
